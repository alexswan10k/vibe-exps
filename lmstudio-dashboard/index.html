Connection & CORS

Checking CORS headers…
Why this works from file:// (and when it doesn’t)

Good news: LM Studio’s local server already sends Access-Control-Allow-Origin: * and Access-Control-Allow-Headers: * on every /v1/* and /api/v0/* endpoint. That means fetch() from a file:/// page (Origin: null) succeeds in Chrome, Edge, and Firefox without any proxy.

If you see “Failed to fetch”:

  • Make sure LM Studio → Local Server is Running (port 1234 by default).
  • Check the endpoint above matches the port shown in LM Studio. Try http://localhost:1234 or http://127.0.0.1:1234.
  • Safari is stricter with file:// + null origin — open via a tiny local server instead:
    python3 -m http.server 8000 or npx http-server . then visit http://localhost:8000/lmstudio-dashboard.html
  • No extra CORS proxy is needed. If you self-host elsewhere, ensure the server still sends ACA-Origin: *.

Bypass attempt built-in: this dashboard automatically retries /api/v0/models → /v1/models, handles Origin: null, and surfaces the exact CORS error so you can see what’s blocked.
